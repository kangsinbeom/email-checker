# email-checker 설계

용어는 `CONTEXT.md`를 따른다. 이 문서는 2026-10-08 인터뷰에서 정한 동작을 적는다.

## 흐름

1. **매일 07:00 KST** 디스코드 bot이 네이버·Gmail 받은편지함(IMAP, 앱 비밀번호)에서 새 메일을 가져온다. 첫 실행은 **기존 메일** 전부를 가져온다.
2. 새 메일마다 **분류**한다.
   - 발신자 규칙(`rules.toml`: **지정 뉴스레터** 주소, 국방부 도메인)에 걸리면 **확인**.
   - 나머지는 Laya `multilingual` 모델(재학습 후에는 재학습된 모델)이 판단한다. 확신이 보류 기준값보다 낮으면 **보류**.
3. 아직 **검토**되지 않은 메일 전부를 **보고서** CSV(`id, 분류, 제목, 보낸 사람, 링크`)로 디스코드 채널에 올린다. 전날 검토하지 않은 메일도 계속 실린다.
4. 사용자가 CSV의 `분류`를 고쳐 채널에 올리면 **검토**로 처리한다.
   - `삭제`/`확인`인 줄은 정답으로 기록한다(고치지 않은 줄 포함). `보류`로 남은 줄은 검토되지 않은 것이다.
   - 정답이 `삭제`인 메일을 그제야 휴지통으로 옮긴다. **검토 없이 지우는 일은 없다.**
   - 분류별 정확도를 답장으로 알려 준다.
5. 사용자가 `제목, 본문, 정답(, 보낸 사람)` CSV를 올리면 **예시 데이터**로 저장한다.
6. 4나 5로 정답이 새로 생기면 **재학습**한다.
   - **학습자료** 전체로 `multilingual`에서 새로 학습한다(CPU — MX450은 메모리 부족).
   - 실제 메일 중 일부(id % 5 == 0)는 시험용으로 떼어 둔다. 예시 데이터는 학습에만 쓴다.
   - 새 모델의 시험 정확도가 현재 모델 이상일 때만 교체하고, 결과를 채널에 알린다.

## 운영

- **서버 노트북**에서 systemd 서비스 하나(디스코드 bot)로 돈다. 코드는 Mac → GitHub(`kangsinbeom/email-checker`, PUBLIC) push → 서버 pull로 보낸다.
- MX450(사용 가능 1.64GiB)은 학습뿐 아니라 추론에서도 OOM이 나서, 분류와 재학습 모두 CPU로 한다.
- 비밀값은 서버의 `.env`에만 둔다(`NAVER_USER`, `NAVER_APP_PASSWORD`, `GMAIL_USER`, `GMAIL_APP_PASSWORD`, `DISCORD_TOKEN`, `DISCORD_CHANNEL_ID`).
- 채널에 `!보고서`를 보내면 07:00을 기다리지 않고 바로 보고서를 만든다(첫 실행용).

## 알려진 한계

- 네이버 메일별 링크 형식을 모른다. 네이버 메일은 링크 칸이 비고, 제목과 보낸 사람으로 찾는다.
- Gmail 링크는 브라우저의 첫 번째 로그인 계정(`/u/0/`)을 가정한다.
